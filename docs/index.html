The problem: integration rot

Every third-party API you ship against is a liability with a timer on it. The blast radius hides across repos until a vendor flips the switch.

🕵️

Deprecations hide in plain sight

Sunset notices live in changelogs nobody reads. The deprecated call sits in billing/worker.py for two years — until it starts returning 410s.

🧩

Migrations are toil, not engineering

Each vendor migration is the same shape: find every call site, rewrite args, prove the new contract. It's mechanical work that eats senior-engineer weeks.

🫥

Silent drift breaks you first

Vendors change fields and endpoints without a formal deprecation. Your integration keeps "working" while the data it returns quietly changes shape.

How it works

Four stages, one pipeline. Every transcript below is real output captured from running the tool — no mockups.

01

Scan

integration-rot scan

Inventory every third-party dependency and find hardcoded vendor API calls. Parses package.json, requirements.txt, go.mod, Gemfile and pom.xml, maps ~45 SDK packages to vendors, and heuristically spots vendor hostnames in source.

scan

02

Match & rank

integration-rot check

Cross-reference the inventory against a curated knowledge base of 17 real deprecations. Risk is ranked by days-to-sunset and severity; exit code 1 on critical/high — built for CI gates and Markdown/JSON reporting.

03

Draft the fix

integration-rot fix

Generate a real unified diff plus a contract test that proves the new API contract. Five migration drafters ship today: Stripe Charges→PaymentIntents, Twilio Authy→Verify v2, SendGrid v2→v3, Plaid /transactions/get→/transactions/sync, Slack RTM→Socket Mode.

fix
$ integration-rot fix demo/sample-app --entry stripe-charges-api --file app.py
--- a/app.py
+++ b/app.py
@@ -13,11 +13,13 @@

 def create_charge(amount_cents, currency, token, description=""):
     """Charge a card using the legacy Charges API (deprecated pattern)."""
-    charge = stripe.Charge.create(
+    charge = stripe.PaymentIntent.create(
         amount=amount_cents,
         currency=currency,
-        source=token,
+        payment_method=token,
         description=description,
+        confirm=True,
+        automatic_payment_methods={"enabled": True, "allow_redirects": "never"}
     )
     return charge

--- generated contract test: tests/test_stripe_payment_intent_contract.py ---
Notes:
  - rewrote 1 stripe.Charge.create call(s) to stripe.PaymentIntent.create (SCA-ready)
  - verify with stripe-mock or Stripe test clocks before merging
04

Prove & propose

integration-rot verify + drift + propose

Execute the migration, don't just draft it: run the contract tests in an isolated sandbox before anything touches your repo. Catch the changes vendors don't announce: diff a pinned OpenAPI snapshot against the live spec — or track drift over time with timestamped snapshot history. Then open the PR — risk finding, diff, contract test and reviewer notes all attached.

verify + drift + propose

What you get

A complete loop from detection to merged PR — not another dashboard that just tells you you're doomed.

📚

Curated deprecation DB

17 real, sourced deprecations across 13 vendors. Every entry links its announcement — no invented sunsets.

🎯

Risk-ranked findings

Critical/high/medium/low by days-to-sunset and severity. Exit code 1 on serious findings — gate your CI.

🔧

Migration drafters

Real unified-diff patches for 5 migrations: Stripe, Twilio Verify, SendGrid v3, Plaid sync, Slack Socket Mode.

🧪

Contract tests

Every draft ships a pytest contract test asserting the new API's parameter contract. Proof, not vibes.

🔭

Schema-drift detection

Diff pinned OpenAPI snapshots against live vendor specs — or keep a timestamped drift history. Catches the changes nobody announced.

📬

PR proposer

Opens GitHub PRs carrying the risk report, diff, contract test and reviewer notes. Draft-PR mode included.

Roadmap

v0.3.0 is the working core — verified, not just drafted. Next: deeper fixes, team workflow, vendor partnerships.

v0.3 — shipped ✓
  • RSS/Atom changelog scanning with deprecation-signal matching
  • Timestamped OpenAPI snapshot history + CI-friendly drift exit codes

  • 3 new fixers: GitHub query-auth, Salesforce versions, Mailchimp v2

  • GitHub App: install on an org, PRs on a schedule

  • Per-repo policy file (rot.toml)

Quickstart

Python ≥ 3.10, zero runtime dependencies. Sixty seconds to your first report.

quickstart

$ cd integration-rot && python -m pip install -e ".[dev]"
$ integration-rot demo          # full pipeline on the bundled sample app
$ integration-rot check /path/to/your/repo
